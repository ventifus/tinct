### Theoretical Verification

#### 1. Value::Dict with Arc<Thunk> — letrec correctness

**Model:** Launchbury (1993) natural semantics for lazy evaluation; letrec
allocation requires all bindings to be allocated as pending thunks before any body
is forced.

**Verification:** eval_dict_core (eval_dict.rs:248-442) correctly implements
two-phase letrec:
- Phase 1: All static-key entries are collected as `(slot_idx, Arc<Thunk>)` tuples
  in `letrec_slots` (line 274).
- Phase 2: Batch fill — first `reserve_slot` for all entries (lines 416-422), then
  `fill_slot_arc` for all entries (lines 423-425).
- The same `Arc<Thunk>` is placed in both `dict_map` and the ScopeArena scope
  (via `fill_slot_arc`). This preserves thunk identity — settling the thunk via
  either reference settles it for both, which is the call-by-need memoization
  guarantee.

**Arc cycle risk (T-1774):** Dict entries hold `Arc<Thunk>`. Those thunks hold
`UnevaluatedState::CoreExpr { env_id, ctx }` where `env_id` is a u32 index (not
an Arc) and `ctx` is `Arc<EvalContext>`. The EvalContext holds
`Rc<RefCell<ScopeArena>>` which holds `Arc<Thunk>`s. This is the pre-existing
`ctx -> arena -> thunks -> ctx` reference cycle. The Dict migration to `Arc<Thunk>`
does NOT introduce any new cycle path — the same thunks were already reachable
through the ScopeArena. The Dict merely adds a second Arc strong reference to the
same Thunk objects that the arena already holds. No new cycle risk from T-1772.

**VERDICT: SOUND.** The two-phase letrec invariant is maintained. Thunk identity
preservation is correct. No new Arc cycle paths.

#### 2. merge_env_chain_into two-pass — scoping correctness

**Model:** Damas-Milner let-polymorphism (1982) — each `let` binding introduces
a new scope that shadows the same name in the enclosing scope.

**Verification:** The function (env.rs:745-826) implements two-pass merging:
- Pass 1 (lines 762-804): Collects entries from the src chain using `or_insert_with`.
  Frames are iterated innermost-first (line 766 iterates `frames.iter()` where
  `frames[0]` is the innermost scope). `or_insert_with` means the first insertion
  wins — inner scope shadows outer scope within the chain. This is correct lexical
  scoping.
- Pass 2 (lines 807-826): Inserts collected entries into `dst` using `insert`
  (unconditional overwrite). This implements cross-document shadowing: later documents
  override earlier documents' bindings. This is right-biased merge semantics,
  consistent with tinct's `merge` operator.

**Scoping model:** Within a single document's scope chain, inner let-bindings shadow
outer ones (standard Damas-Milner). Across documents, later documents shadow earlier
ones (multi-file pipeline semantics). The two-pass design correctly separates these
two shadowing dimensions.

**All six binding categories are merged:** slots, extras, type_aliases, classes,
instances, tycon_defs. This is complete — no binding category is silently dropped.

**VERDICT: SOUND.** The two-pass semantics are consistent with Damas-Milner scoping
within documents and right-biased merge across documents.

#### 3. Span compaction — error message quality

**Model:** Error messages must provide enough information for the user to locate and
understand the error. Source snippets are an enhancement, not a requirement. The
minimal requirement is file + line + column.

**Verification:**
- Span retains: `file: Arc<str>`, `start_line: u32`, `start_col: u32`,
  `end_line: u32`, `end_col: u32`, `name: Option<Arc<str>>`.
- Span Display: `"file:start_line:start_col-end_line:end_col"` — full location info.
- Source snippet rendering: `render_span_snippet(source, span)` is available as a
  public helper. Callers that have the source text (CLI, tests, parser) use it.
- EvalError::Display: no longer renders inline snippets. This is documented at
  error.rs:1523-1525 with a T-1771 reference.
- `write_frame_snippet` is a no-op (error.rs:1506-1508).
- CLI integration: `format_type_diagnostic` (main.rs:2488) calls
  `render_span_snippet` with the source text.
- doc/10-errors.md and doc/feature/source-text-availability.md both document the
  caller-provides-source design.

**Degradation path:** The loader (loader.llt, test-loader.llt) formats errors
using a tinct-level `format-diagnostic` function that has no access to source text
— it formats location coordinates only. This means errors from included files
(loaded via the tinct-side loader pipeline) will not show source snippets in the
tinct-formatted error output. The CLI's top-level error handler only renders
snippets for the init program's source, not for sources loaded by `include`.

This is a known limitation of the caller-provides-source design (same as Nickel's
`to_diagnostic(files)` pattern). A future improvement would be to thread a source
registry through the error chain, but this is not a regression — the pre-sprint
code also did not embed source text in spans for included files.

**VERDICT: ACCEPTABLE.** Error location information is preserved. Snippet rendering
is available where source text is available. The design matches established practice
(Nickel, rustc).

#### 4. builtin-lower — interface soundness

**Model:** The pipeline stages form a defunctionalized continuation chain
(Ager, Biernacki, Danvy & Midtgaard, 2003). Each stage consumes the output of the
previous stage and produces input for the next. The interface must be type-correct
at each boundary.

**Verification:**
- `builtin-lower` (builtins_meta.rs:5409-5486) accepts `Value::Document` and
  produces `Value::CoreDocument { entries, span }`.
- `entries` is `Arc<Vec<(String, Arc<Spanned<CoreExpr>>)>>` — each entry is a
  (key_name, lowered_expression) pair.
- Lowering uses `crate::lower::lower(node, scope_frames)` — the standard lowering
  function. Lower diagnostics are converted to `EvalError` via
  `lower_errors_to_eval_error`. This is correct — lowering errors are eagerly
  reported.
- Decl items are correctly skipped (line 5455: `SurfaceItem::Decl(_) => continue`),
  and `expr_idx` is incremented only for Expr items. This ensures key contiguity.
- The test `builtin_lower_skips_decl_items.llt-eval` verifies this.

**Interface gap:** `builtin-eval` does not accept `CoreDocument`. The lowered
representation cannot be fed into eval. This is tracked above as fix-later finding 3.

**Can all valid programs be lowered before eval?** Yes. `lower()` is a pure function
of the `SurfaceNode` and inline OnceLock fields. It requires no runtime state. Any
resolved+typechecked document can be lowered. The only constraint is that scope_frames
must be available for `call_dispatch` resolution — this is threaded through the
EvalContext.

**VERDICT: SOUND** for the lowering step itself. The lowering function is correct and
produces well-formed CoreExpr. The pipeline integration gap (CoreDocument not consumed
by eval) is a completeness issue, not a soundness issue.

### Axiom Verification

**Prelude speaks the Rust protocol:** PASS.
Rust defines: `Value::Dict(IndexMap<HashableValue, Arc<Thunk>>)`,
`Value::CoreDocument`, `builtin-lower`, `builtin-eval`, `merge_env_chain_into`.
Prelude implements the protocol through standard tinct code. No prelude-specific
behavior embedded in Rust. The `builtin-lower` step is a protocol extension — it
defines a new pipeline step that the loader can optionally use.

**No fast paths, no fallbacks, no backwards compatibility:** PASS.
The Dict representation changed from ThunkId to Arc<Thunk> — one correct path.
The old ThunkId-based Dict path is removed. `write_frame_snippet` is a no-op
(not a fallback — it delegates to callers who have source text). The Builder
type's `AtomicBool` frozen check (value.rs:399) is documented as a "fast-path"
in comments — but this is a mutex-avoidance optimization, not a semantic fast
path. The frozen check and the mutex guard check are redundant but not divergent
(both return the same error for frozen builders).

**Correctness, not performance:** PASS.
The `letrec_slots` batch-fill pattern (eval_dict.rs:407-426) reduces borrow overhead
but does not change semantics. The two-phase reserve-then-fill maintains the letrec
invariant correctly. No complexity was added to skip a check or avoid an allocation.

**Loader/prelude agnosticism:** PASS.
`builtin-lower` operates on `SurfaceDocument` and `SurfaceNode` — it does not
reference any prelude type names. `merge_env_chain_into` operates on generic `Env`
frames with no prelude-specific binding names. The span compaction is universal.

**General case, not specific:** PASS.
`merge_env_chain_into` solves the general scope-chain flattening problem (any chain,
any depth, any number of binding categories). `builtin-lower` lowers any document,
not just specific patterns. No special cases.
