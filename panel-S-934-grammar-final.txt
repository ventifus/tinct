### Axiom Check

**Prelude speaks the Rust protocol** — PASS. The `Annotation::Quote` sentinel is produced by the parser (Rust), not the prelude. The `is_expr_annotation` function is a Rust-level check independent of prelude bindings. `expression_to_annotation` hardcodes `"Expr"` as the sentinel name, which reserves it at the language level — this is intentional and documented in ast.rs:208-211.

**No fast paths, no fallbacks, no backwards compatibility** — PASS. The `Annotation::Annotated` outer changed from `String` to `Box<Annotation>`. The surface_fields.rs serialization code at line 629-643 preserves backward-compat wire format for `Simple` outers via the `name` key, but this is the serialization protocol, not a parser fast path. The comment at 625 says "backward compatibility" which is worth watching but is in the wire protocol layer, not the parser. Not flagged as a violation.

**Correctness, not performance** — PASS. `set_floating_annotation` now returns `Result<(), ParseError>` instead of silently doing nothing when the stack top is not a Dict. This is strictly more correct — the old behavior would have silently discarded the annotation.

**Loader/prelude agnosticism** — PASS with documentation caveat. The `@Expr` sentinel reserves the name `Expr` in annotation position at the parser level (any `@Expr` annotation becomes `Annotation::Quote` regardless of whether the user's prelude has a type named `Expr`). This is documented in ast.rs:208-211. The annotation-based narrowing (T-1761) is fully prelude-agnostic: any user function annotated with `@[narrows: T]` or `@[is: T]` participates in narrowing without hardcoded names.

**General case, not specific** — PASS. `expression_to_annotation` handles VarRef, annotated VarRef, Dict, implied Call, and falls back to a single-entry PropertyDict — covering the general case. The `set_floating_annotation` function checks for Dict frame generically, not for a specific Dict context.
