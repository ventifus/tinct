### Detailed Findings

**F-01 (Nit / fix-now): `get_thunk_rc` stale name**
`eval.rs:2141` — `fn get_thunk_rc(thunk: &Arc<Thunk>) -> Arc<Thunk> { Arc::clone(thunk) }`. The "rc" suffix is a leftover from the Rc-based pre-T-1772 design. The comment at line 2138 says "Clone an Arc<Thunk> from a dict entry for tests that need direct thunk access (e.g. inspecting ThunkState or materializing with a custom mat_span). After T-1772, dict values are Arc<Thunk> directly — no ThunkId lookup needed." The name should match the type. Fix: rename `get_thunk_rc` → `get_thunk_arc` (or simply `get_thunk`) across all call sites in eval.rs tests (lines ~2310, 2367, 2955, 3380, 3485). This is internal test-only code with no public surface.

**F-02 (Nit / fix-now): `surface_fmt.rs` dead `ctx` parameter**
`surface_fmt.rs:59` — `let _ = ctx; // ctx no longer needed for thunk access (T-1772)`. The parameter is received but immediately discarded. If `ctx` is still needed for `value.to_tinct(ctx)?` at line 65, it must not be discarded. If it is not needed, the parameter should be removed (or at minimum the `let _ = ctx` removed and the parameter marked with a path-to-removal comment). The current code is confusing: `ctx` is used at line 65 but shadowed-discarded at line 59. Reading the code, `ctx` IS passed to `value.to_tinct(ctx)` at line 65, so the `let _ = ctx` at line 59 is just a comment artifact and the parameter is still used. The comment "ctx no longer needed for thunk access" is misleading — it is still needed for Function serialization. Fix: remove the `let _ = ctx;` line entirely and update the comment to clarify ctx is still needed for Function values.

**F-03 (Minor / fix-now): `merge_env_chain_into` tests cover only `tycon_defs`**
`src/env.rs:908-1043` — All five unit tests use only `insert_tycon_def` / `lookup_tycon_def`. The function merges six field types: `slots`, `extras`, `type_aliases`, `classes`, `instances`, `tycon_defs`. The two-pass semantics (inner-wins via or_insert in Phase 1, later-doc shadows via insert in Phase 2) apply identically to all six. Cross-document shadowing of `slots` (type schemes in the type-check env) is untested. Fix: add at least one test that exercises `slots` shadowing (e.g. use `insert_slot`/`get_slot` to verify inner-wins and dst-shadows semantics hold for the runtime value field).

**F-04 (Major / fix-later): `builtin-lower` → `builtin-eval` pipeline gap**
`src/builtins_meta.rs:3599` — `builtin-eval` accepts only `Value::Document` and errors with `type_mismatch_ctx("Document", other.type_name(), call_span)` for any other input including `Value::CoreDocument`. `builtin-lower` at line 5409 produces `Value::CoreDocument` containing pre-lowered `Arc<Spanned<CoreExpr>>` entries. `lib.rs:686` rejects `CoreDocument` with `value_not_serializable`. The "parse → desugar → resolve → typecheck → lower → eval" pipeline is therefore broken at the lower→eval seam: nothing can consume a `CoreDocument`. The intended completion path is for `builtin-eval` to accept `CoreDocument` and evaluate its pre-lowered entries via `eval_core_expr` directly, bypassing the inline lowering in `eval_document_exprs_with_env`. This is a pre-existing design gap not introduced by S-947. Tracked as future work; create tracker item if not already present.

### Axiom Verdicts

- **Prelude speaks the Rust protocol**: PASS. Rust defines `Arc<Thunk>` dict layout; prelude accesses via `builtin-get`, `builtin-dict-nth`, etc. No Rust-embedded prelude assumptions.
- **No fast paths, no fallbacks, no backwards compatibility**: PASS. Dict migration is a clean replacement. No ThunkId fallback in any dict access path. HashableValue::Str uses Arc<str> everywhere with no Rc<str> fallback.
- **Correctness, not performance**: PASS. Arc<Thunk> is slightly larger than ThunkId but provably correct and enables span access without arena round-trip.
- **Loader/prelude agnosticism**: PASS. Dict layout change is transparent to tinct code; no loader-specific handling.
- **General case, not specific**: PASS. `migrate_value` Value::Dict branch handles all migrated dicts uniformly; no special-casing. `translate_unevaluated_state` handles all UnevaluatedState variants correctly.
