### Findings

---

FINDING: Axiom violation — backwards compatibility fallback in Annotation::Annotated
serialization. surface_fields.rs emits BOTH "inner" (Display string) and "inner-ann"
(structured recursive Annotation value) for every Annotated variant. The deserializer in
surface_convert.rs tries "inner-ann" first, then falls back to "inner" as a backward-compat
path. Since the serializer always emits "inner-ann", the "inner" field and the fallback in
the deserializer are dead code that exists solely for backwards compatibility — an explicit
axiom violation. Fix: remove the redundant "inner" field from the serializer (surface_fields.rs
lines 648-653) and remove the fallback to "inner" in the deserializer
(surface_convert.rs lines 783-785). Only "inner-ann" should be used in both directions.
| SCOPE: fix-now | FILE: src/surface_fields.rs:644 and src/surface_convert.rs:783

---

FINDING: Arity mismatch error message is misleading for builtin-typecheck-doc.
builtins_meta.rs line 2682 accepts 2 or 3 args but uses `EvalError::arity_mismatch(2, …)`
which produces "expected 2, got N". For N=1 or N≥4, user sees a confusing message since the
function actually accepts 2 or 3. Fix: use `EvalError::arity_mismatch_bound(ArityBound::Range(2, 3), args.len(), call_span)` (ArityBound::Range already exists for this case).
| SCOPE: fix-now | FILE: src/builtins_meta.rs:2683

### New Feature Integration: builtin-scope-frame (display chain)

Registration: PASS. builtins_core.rs lines 598-604 registers "builtin-scope-frame"
with Strictness::Seq, arity 1. builtin_scope_frame returns {name: Int(slot)} for all
slots whose thunk has a span.name set.

Span name propagation: PASS. eval_dict_core sets span.name via with_name() for all
string-keyed entries (line 286-292). So tinct dict literals like [%: ev.result] cause
the thunk for ev.result to carry span.name = "%", making it visible to builtin-scope-frame.

scope-to-frames in test-loader.llt: PASS. _scope-to-frames-inner walks the parent chain
from innermost to outermost via builtin-scope-parent, prepending each level's frame.
The resulting frames array matches resolve.rs ordering (initial_frames[0] = outermost).
builtin-resolve (lines 2390-2434) consumes the frames correctly.

"Clean scope" pattern (line 671 of test-loader.llt): PASS BY DESIGN.
[builtin-scope-new st.scope-id [builtin-scope-frame ev.scope-id]] creates a scope
whose own slots contain Int values (not named thunks), so builtin-scope-frame of this
new scope returns empty. Resolve frames come from the parent chain (st.scope-id and
ancestors). This intentionally prevents % pollution in multi-doc pipelines. Second-doc
code can only access first-doc results via %, not by name — correct pipeline semantics.

### Axiom Verdicts

- Prelude speaks the Rust protocol: PASS for T-1761 (param_narrowings protocol defined
  in Rust; prelude implements via @[is: T] / @[narrows: T]). Pre-existing B-545 violation
  for structural narrowing hardcoded names — not introduced in this sprint.

- No fast paths, no fallbacks, no backwards compatibility: FAIL — "inner" string field +
  deserializer fallback in Annotation::Annotated Variant serialization. See finding above.

- Correctness, not performance: PASS. No performance shortcuts observed. The
  drop_range_and_truncate path (S-946) is provably correct. eval_annotation_property_dict
  materializes non-literal values correctly via lower+eval+materialize.

- Loader/prelude agnosticism: PASS for new features. T-1761 is fully annotation-driven;
  no predicate names are hardcoded in Rust. builtin-scope-frame is a general mechanism.

- General case, not specific: PASS. param_narrowings is a general Vec (any param can
  declare narrowing). builtin-scope-frame works for any scope, not just specific patterns.
