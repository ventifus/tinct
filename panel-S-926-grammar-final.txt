**GENUINE REMAINING ISSUE — fix-now**

FINDING: Three corpus tests use `--- %@Type` which is a parse error per spec and code,
but expect successful (or wrong-error) evaluation. | SCOPE: fix-now |
FILE: tests/corpus/eval/pipeline/input_validation_percent_at.llt-eval:5
      tests/corpus/eval/pipeline/input_validation_record_type.llt-eval:5
      tests/corpus/eval/errors/input_validation_mismatch.llt-eval:5

The form `--- %@Dict` lexes as `Identifier("%") ImmediateAt Identifier("Dict")` because
`@` is not a bare-word char (src/lexer.rs:1076). The parser (src/parser.rs:3561-3581) sees
key `"%"`, trims `%` to get empty `section_name`, sees `ImmediateAt` next, and returns a
ParseError: "bare '%' in section header: expected a name after '%' (e.g. '--- %name' or
'--- %name@Type')".

The doc grammar at doc/09-documents.md:551 is unambiguous:
  `section_name = "%" ~ ident_char+`
At least one ident char is required after `%`. `%@Dict` has zero. This is intentionally
invalid — the parser and spec agree.

Affected tests and their incorrect expectations:
- `input_validation_percent_at.llt-eval`: uses `--- %@Dict`, expects `Dict({"merged": ...})`
  (successful eval) — will fail with parse error instead.
- `input_validation_record_type.llt-eval`: uses `--- %@[host: String port: Int]`, expects
  `Dict({"url": String(...)})` (successful eval) — will fail with parse error instead.
- `input_validation_mismatch.llt-eval`: uses `--- %@Dict`, expects a runtime dot-access
  error — will fail with parse error before reaching eval.

Fix: Replace `--- %@Type` with `--- expects: @Type` in all three tests. This is the
supported syntax for pipeline input type annotation (`expects:` key-value header entry).
No parser code change needed; `%@Type` is correctly a parse error.

Concretely:
- input_validation_percent_at.llt-eval:5  — `--- %@Dict` → `--- expects: @Dict`
- input_validation_record_type.llt-eval:5 — `--- %@[host: String  port: Int]`
                                             → `--- expects: @[host: String  port: Int]`
- input_validation_mismatch.llt-eval:5    — `--- %@Dict` → `--- expects: @Dict`
