F-03 | value.rs — DirCap Clone try_clone().expect() needs SAFETY comment (lines 721-728)
STATUS: VERIFIED

src/value.rs lines 722-727 now contain:
  // SAFETY: DirCap values are always created from valid OS file descriptors
  // (main.rs and builtins_io.rs construction sites). try_clone() can fail with
  // EMFILE (too many open files) or EBADF (invalid descriptor) only if the
  // descriptor is closed or the fd table is exhausted. DirCap values are assumed
  // to remain valid for their Arc lifetime — the descriptor is never explicitly
  // closed while a DirCap holding it is alive.
Comment explains both failure modes and the invariant. Correct.

Note (nit, not blocking): RevocableDirCap at line 738 uses the same try_clone().expect()
pattern without a SAFETY comment. This was not in scope for F-03 (which referenced
lines 721-735) and was not flagged by the round 1 verifier. Noted for future cleanup
but does not affect this verdict.
