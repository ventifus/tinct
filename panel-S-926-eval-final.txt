## Review: eval-engine (S-926 thin-meta-api, THIRD PASS)

### Findings

- FINDING: `prelude.llt:3383` — `[raise ev.errors]` passes `{0: String}` Dict to `raise`, which requires String. When `builtin-eval` returns an error, `ev.errors` is `{0: "message string"}`. `raise` calls `require_string()` (builtins_meta.rs:200), which will fail with a type mismatch error rather than surfacing the actual eval error. The sprint correctly fixed loader.llt:362 (`[builtin-raise [builtin-get 0 ev.errors]]`) and test-loader.llt:373,520 to use `[builtin-get 0 ev.errors]`, but missed the identical pattern in `prelude.llt`'s `eval-program` function. The fix is identical: `[raise [builtin-get 0 ev.errors]]`. | SCOPE: fix-now | FILE: stdlib/prelude.llt:3383

### Verdict

REQUEST_CHANGES

The `[raise ev.errors]` in `stdlib/prelude.llt:3383` is a correctness bug. When `builtin-eval` fails, the error propagation produces a secondary type mismatch error ("expected String, got Dict") instead of the actual eval error. The identical fix applied to loader.llt and test-loader.llt must also be applied here: `[raise [builtin-get 0 ev.errors]]`.
