### Findings

FINDING: I2 fix (errors schema) complete in Rust, but callers in loader.llt
and test-loader.llt were not fully updated. `[builtin-raise ev.errors]` passes
the new `{0: String(message)}` Dict to builtin_raise, which calls
require_string and will type-error ("raise: expected String, got Dict") instead
of raising the original eval error. This breaks the error path of EVERY
builtin-eval call in both loaders. Five call sites affected:
  - stdlib/loader.llt:362   [builtin-raise ev.errors]
  - stdlib/loader.llt:458   [builtin-raise eval-result.errors]
  - stdlib/loader.llt:459   [builtin-raise eval-result.errors]
  - stdlib/test-loader.llt:373  [builtin-raise ev.errors]
  - stdlib/test-loader.llt:520  [builtin-raise ev.errors]
Fix: Replace each with [builtin-raise [builtin-get 0 ev.errors]] (or
equivalent extraction of the message string from the errors dict).

### Verdict
REQUEST_CHANGES

The I2+I5 fix pair is incomplete. The Rust side (builtins_meta.rs) correctly
produces {0: String} on error, but the tinct callers in loader.llt and
test-loader.llt still pass ev.errors (now a Dict) directly to builtin-raise
(which requires a String). Any document that fails during eval will produce a
confusing secondary type-mismatch error instead of the original error message.
This is a critical regression on the error path of the core loading pipeline.
