### Axiom Compliance Sweep

**Prelude speaks the Rust protocol**: PASS
`as_type_dispatch` in `src/typecheck_annot.rs:4916` defines the `as-typenode` protocol
contract. Rust specifies the name and calling convention; prelude implements it. The
annotation-based narrowing mechanism (`@[is: T]`, `@[narrows: T]`) similarly defines a
protocol that prelude functions opt into via annotations — no names hardcoded in Rust.

**No fast paths, no fallbacks, no backwards compatibility**: PASS
The true/false arms in `try_eq_literal` were removed (return None, not Unknown). The
Bool/Seq arms in `try_type_of` were corrected (return None, not Unknown). No dead
compatibility shims introduced. The `as_type_dispatch` function returns None on all
error paths rather than falling back to Unknown.

**Correctness, not performance**: PASS
`try_eq_literal` and `try_type_of` now return the provably correct result (no narrowing)
for cases where no type information is statically available. No shortcuts were taken.

**Loader/prelude agnosticism**: PASS
Predicate narrowing is now entirely annotation-driven — any prelude can name predicates
anything and add `@[is: T]` annotations. The `as-typenode` dispatch is a named protocol
entry (D-7), not embedded behavior. The gap in B-546 (fn?/seq? lacking @[is: T]) is a
prelude authorship issue, not a language feature dependency.

**General case, not specific**: PASS
The annotation-based narrowing mechanism generalizes to all predicates in any prelude
via `@[narrows: T]` / `@[is: T]`. The structural pattern narrowing (`=`, `and`, `has?`,
`type-of`) uses hardcoded names tracked as B-545 — a known remaining violation deferred
to a future sprint.
