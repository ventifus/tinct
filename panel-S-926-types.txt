- T1 RESOLVED: `type_errors` field added to `TypeContextData` (eval.rs:365) as `Vec<crate::types::TypeError>`.
  Initialized to `Vec::new()` in `builtin_make_type_ctx` (builtins_meta.rs:2628). Accumulated via
  `guard.type_errors.extend(errors)` in `builtin_typecheck_doc` (builtins_meta.rs:2528). The `errors`
  value is the third element of the tuple returned by `typecheck_surface_document`, which includes both
  advisory and non-advisory errors (both merged into `advisory_errors` at typecheck.rs:764 before return).
  Type chain: `crate::types::TypeError` resolves via `types.rs` → `pub use type_env::*` → `TypeError`
  in type_env.rs. Accumulation is correct.

- T2 RESOLVED: `typecheck_surface_document_native` is absent from all source files. Grep confirms zero
  matches across the entire src/ tree.

- T3 RESOLVED: `ThunkArena` is absent from all source files. `FlatEnv` terminology in comments refers
  to the actual internal struct name (not a stale artifact). Comments consistently use `ScopeArena` /
  `scope_arena` for the arena concept introduced in S-925.

- OBSERVATION (not fix-now): `init_type_context` doc comment (eval.rs:990) states "logs a warning" on
  double-initialization but the implementation (eval.rs:993-996) silently no-ops with no log. Minor doc
  inaccuracy. Not type-system related; fix-later.

  `TypeContextData` into a fresh `Arc<Mutex<>>`, disconnecting it from `EvalContext.type_context`. The

  on handles obtained via `builtin-get-type-context` would not be visible on the EvalContext's handle.
  This is documented as vestigial behavior; callers should use `builtin-make-type-ctx`. Not a bug in
  the sprint's fix.
